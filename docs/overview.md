# Obsidian TaskMaster — обзор проекта

## Суть продукта

**Obsidian TaskMaster** — плагин для Obsidian, предназначенный для проектных менеджеров. Позволяет управлять задачами через визуальную доску с четырьмя фиксированными группами и структурированными карточками задач в стиле SMART.

Ключевое отличие от существующих решений: это **единый опционированный плагин**, который из коробки предлагает методологию управления задачами проектного менеджера — без необходимости собирать workflow из нескольких плагинов или настраивать кастомные поля.

---

## Основные возможности

### 1. Управление задачами (CRUD)

- **Создание** задачи с заполнением структурированных полей
- **Редактирование** деталей задачи
- **Изменение статуса** (в работе, завершена)
- **Удаление** задач

### 2. Группы задач (4 рабочих + 2 служебных)

Задачи организованы в 6 групп: 4 рабочих на основной доске и 2 служебных (сворачиваемых).

**Служебные группы:**

| Группа | Назначение |
|--------|-----------|
| **Бэклог** | Входящие задачи, которые пока не взяты в работу. Очередь задач на будущее |
| **Завершённые** | Архив выполненных задач. Для ретроспективы и анализа. Автоочистка по сроку хранения (по умолчанию 30 дней). Срок настраивается в popup «...» группы. Отдельные задачи можно удалить вручную, не дожидаясь истечения срока |

**Рабочие группы (основная доска):**

| Группа | Назначение |
|--------|-----------|
| **Фокус** | Задачи, которые требуют пристального внимания. То, что нужно держать в поле зрения прямо сейчас |
| **В работе** | Задачи, которые я выполняю лично в данный момент |
| **Орг. намерения** | Задачи, запланированные на текущую неделю. Цели, которые нужно выполнить до конца недели |
| **Делегировано** | Задачи, переданные подчинённым/коллегам. Требуют периодической проверки статуса и контроля |

### 3. Карточка задачи в стиле SMART

Каждая задача содержит набор структурированных полей:

| Поле | Описание |
|------|----------|
| **Что** (What) | Описание задачи — что конкретно нужно сделать |
| **Зачем** (Why) | Цель — зачем это нужно, какой результат ожидается |
| **Кто** (Who) | Исполнитель — кто должен это сделать. Свободный текст |
| **Когда** (When) | Дедлайн — к какому сроку нужно завершить задачу |
| **Создана** (Created) | Дата создания задачи — фиксируется автоматически, не редактируется |
| **Приоритет** (Priority) | Важность задачи: `низкий` / `средний` / `высокий`. По умолчанию — `средний` |
| **Статус** (Status) | Текущее состояние: `новая` / `в работе` / `ожидает` / `завершена` |
| **После выполнения** (Follow-ups) | Пост-задачи — короткие пункты о том, что сделать после выполнения задачи. Необязательное поле: до 20 пунктов по 200 символов. См. «Пост-задачи» |

**Статусы задач:**

| Статус | Значение |
|--------|----------|
| **Новая** | Задача создана, ещё не взята в работу. Назначается автоматически при создании |
| **В работе** | Задача активно выполняется |
| **Ожидает** | Заблокирована — ждёт чего-то внешнего (ответа, другой задачи, ресурса) |
| **Завершена** | Задача выполнена |

**Индикация просрочки:** если дедлайн прошёл, а задача не завершена — карточка визуально подсвечивается (красная рамка), сигнализируя о просрочке.

**Связь между группами и статусами:**

Группа отвечает на вопрос «где я слежу за задачей», статус — «что с ней происходит». Это независимые оси с автоматическими переходами:

- Создание задачи в бэклоге → статус автоматически `Новая`
- Перемещение из бэклога в любую рабочую группу → статус становится `В работе` (если был `Новая`)
- Перемещение в «Завершённые» → статус автоматически `Завершена`
- Перемещение из «Завершённых» обратно на доску → статус возвращается в `В работе`
- Перемещение между рабочими группами → статус **не меняется** (задача может быть `Ожидает` в любой из четырёх групп)

### 4. WIP-лимиты групп

Каждая группа поддерживает настраиваемый **WIP-лимит** (Work In Progress) — максимальное количество задач, которое должно находиться в группе одновременно.

**Поведение при превышении лимита:**

- Пока количество задач в группе **в пределах лимита** — фон группы нормальный (нейтральный/зелёный)
- Когда количество задач **превышает WIP-лимит** — фон группы меняется на красный, сигнализируя о перегрузке

Лимит **мягкий** — добавлять и перемещать задачи в группу можно даже при превышении лимита. Красный фон служит предупреждением, а не блокировкой.

**Настройка WIP-лимита:**

- В заголовке каждой группы отображается иконка «...» (многоточие)
- По нажатию открывается popup с настройками группы
- В popup можно задать или изменить значение WIP-лимита
- Текущий лимит отображается в заголовке группы рядом с названием, например: «В работе (3/5)» — 3 задачи из 5 допустимых

### 5. Отмена удаления

При удалении задачи внизу экрана появляется toast-уведомление с кнопкой «Отменить»:

- Toast отображается **7 секунд** с обратным таймером
- Нажатие «Отменить» — задача возвращается в ту же группу, на ту же позицию
- Если toast исчез — задача удаляется окончательно
- При удалении нескольких задач подряд — toast'ы стакаются, каждый со своим таймером

### 6. Сортировка внутри групп

**Ручная сортировка** — основной режим. Пользователь перетаскивает карточки внутри группы drag-and-drop, выстраивая их в нужном порядке. Позиция каждой карточки сохраняется.

**Быстрая автосортировка** (пост-MVP) — разовое действие через меню «...» группы. Пересортировывает карточки по выбранному критерию:

- По дедлайну (ближайшие сверху)
- По статусу (ожидает → в работе → новая)
- По дате создания

После автосортировки результат фиксируется как новый ручной порядок. Автосортировка не «залипает» — пользователь может сразу продолжить двигать карточки руками.

### 7. Перемещение между группами

Карточки задач можно свободно перемещать между всеми группами через drag-and-drop. Примеры сценариев:

- Задача была **В работе** у меня → я её **Делегировал** коллеге
- Задача из **Орг. намерений** перешла **В работу**
- Делегированная задача вернулась в **Фокус** для контроля
- Задача из **Бэклога** взята **В работу** → статус автоматически `В работе`
- Выполненная задача перемещена в **Завершённые** → статус автоматически `Завершена`

### 8. Компактный режим карточек

Плагин поддерживает два режима отображения карточек задач:

**Обычный режим (по умолчанию):**
- Карточка занимает 3 строки
- Показывает: приоритет, статус, дедлайн, описание задачи, исполнителя
- Максимальная читаемость, отображается поле "Зачем" при открытии карточки

**Компактный режим:**
- Карточка занимает 1 строку
- Показывает: иконки (приоритет + статус), исполнителя, описание, дедлайн, кнопку удаления
- Поле "Зачем" скрыто — доступно только в модальном окне редактирования
- Длинные названия автоматически обрезаются с многоточием
- При наведении на обрезанный текст показывается tooltip с полным содержимым
- Дедлайн отображается в сокращённом формате:
  - Задача на текущий месяц → только день: "24"
  - Задача на другой месяц текущего года → месяц-день: "03-24"
  - Задача на другой год → день и сокращённый год: "24 '27"

**Когда использовать компактный режим:**
- Много задач (10+ в группе) — нужен быстрый обзор без прокрутки
- Работа с операционными, короткими задачами
- Важна плотность информации на экране

**Компромиссы:**
- Скрыто поле "Зачем" — цель задачи видна только при открытии карточки
- Меньше визуального пространства для восприятия деталей

Переключение режима: **Settings → TaskMaster → Card view**. Изменения применяются мгновенно ко всем доскам.

### 9. Видимость групп и секции Notes

Каждая доска поддерживает настройку видимости: любую из 6 групп и секцию Notes можно скрыть, чтобы убрать с доски без удаления данных.

**Видимость групп:**

- Скрытые группы не отображаются в раскладке доски
- Задачи в скрытых группах сохраняются — они не удаляются и не перемещаются
- Автоматизации (завершение задач, переходы статусов) работают для задач в скрытых группах независимо от их видимости
- Нельзя скрыть последнюю видимую группу — хотя бы одна должна оставаться видимой

**Видимость секции Notes:**

- Секция Notes (быстрые заметки) может быть полностью скрыта с доски
- Содержимое заметок сохраняется при скрытии и восстанавливается при повторном показе
- Скрытие Notes не влияет на состояние collapse/expand — при показе секция вернётся в то же свёрнутое или развёрнутое состояние, в котором была до скрытия
- По умолчанию Notes видима
- Настройка независима для каждой доски

**Настройка:**

Видимость групп и Notes управляется через popup настроек доски (кнопка «...» рядом с названием доски), в секции «Group Visibility». Рядом с каждой группой отображается счётчик задач в ней (если задач больше нуля). Notes отображается в конце секции, отделённая горизонтальным разделителем (счётчик задач рядом с Notes не отображается — это текстовое поле, а не группа задач).

### 10. Динамический лейаут групп

Каждая доска поддерживает гибкую настройку ширины групп. Для каждой группы независимо можно выбрать один из двух режимов:

- **Полная ширина** — группа занимает всю ширину доски (100%)
- **Половина ширины** — группа занимает половину ширины доски (50%)

**Поведение:**

- Две соседние группы с половинной шириной автоматически выстраиваются бок о бок в одну строку
- Одиночная half-группа (следующая тоже полноширинная или её нет) растягивается до полной ширины
- На узких экранах (менее 600px) все группы принудительно переходят в полноширинный режим
- Скрытые группы не участвуют в расчёте раскладки

**Дефолтный лейаут:**

| Группа | Ширина по умолчанию |
|--------|---------------------|
| Бэклог | Полная |
| Фокус | Половина |
| В работе | Половина |
| Орг. намерения | Полная |
| Делегировано | Полная |
| Завершённые | Полная |

В результате «Фокус» и «В работе» стоят рядом на одной строке, остальные рабочие группы занимают всю ширину.

**Настройка:**

В popup настроек доски («...» рядом с названием доски) отображается таблица с двумя столбцами чекбоксов — «Видимость» и «Полная ширина» — для каждой из 6 групп. Чекбокс «Полная ширина» недоступен для скрытых групп.

### 11. Пост-задачи

У задачи можно записать, что нужно сделать после её выполнения. Пример: «Провести ретро» после «Выпустить релиз». Заводить такую карточку заранее рано, а запись в «Зачем» забудется: закрытая задача уезжает в свёрнутые «Завершённые» и через 30 дней удаляется.

- **Где редактируются.** Блок «После выполнения» в форме задачи, между «Зачем» и «Кто / Когда». Пункт добавляется кнопкой «+ Добавить пункт» или клавишей Enter (новый пункт встаёт сразу после текущего), удаляется кнопкой ✕. Изменения применяются по «Сохранить», Escape их отбрасывает
- **Маркер на карточке.** `↪ N`, где N — число ещё не заведённых пунктов: в обычном режиме слева от дедлайна, в компактном — `↪N` перед дедлайном. При наведении показывается список пунктов. При N = 0 маркера нет
- **Автозаведение.** Когда задача попадает в «Завершённые» из другой группы (кнопкой ☑ или перетаскиванием), каждый незаведённый пункт становится новой задачей в конце бэклога той же доски. У новой задачи «Что» — текст пункта, «Зачем» — «После: » и название родительской задачи, статус «Новая», приоритет по умолчанию. Пункт получает отметку «✓ заведено», и появляется уведомление «Заведено задач в «Бэклог»: N» с текущим названием бэклога. Если бэклог скрыт, к тексту добавляется «(группа скрыта)»
- **Досрочно.** Кнопка «→ в бэклог» у пункта помечает его, и задача заводится при сохранении формы
- **Отмена.** «Отменить» в toast'е быстрого завершения удаляет задачи, заведённые этим завершением, и возвращает их пункты в состояние «не заведено». У перетаскивания отмены нет
- **Не считается завершением:** перестановка внутри «Завершённых» и выбор статуса «Завершена» в форме. Повторное завершение дублей не создаёт
- **Задача в «Завершённых».** Список у неё только для чтения. Нужна пост-задача к уже закрытой задаче — заводится обычная новая карточка

## Интерфейс

### Открытие доски

Доска открывается как **отдельная вкладка** (Obsidian View) — наравне с обычными заметками. Две точки входа:

- **Иконка в ribbon** (левая боковая панель) — основной способ
- **Command Palette** — команда «TaskMaster: Open board»

Если доска уже открыта — повторный вызов переключает на существующую вкладку, а не создаёт дубль.

### Несколько досок

Поддерживается **несколько досок** (по проектам, по активностям, для бытовых задач и т.д.). Переключение — через **селектор в заголовке доски**:

```
┌─────────────────────────────────────────────┐
│  [▼ Проект Alpha]  [+]                      │
│  Разработка MVP таск-менеджера для Obsidian  │
│─────────────────────────────────────────────│
│  ...                                        │
└─────────────────────────────────────────────┘
```

- Выпадающий список — выбор доски
- Кнопка «+» — создать новую доску с дефолтным названием «Новая доска» и пустыми группами. Переименовать можно через popup «...»
- В popup «...» рядом с названием — переименовать / удалить доску / настроить видимость групп и Notes / настроить ширину групп

**Заголовок и подзаголовок доски:**

- **Заголовок** — название доски (отображается в селекторе). Крупный шрифт
- **Подзаголовок** — краткое описание доски (1–2 строки), мелкий шрифт. Необязательное поле — если не заполнено, не отображается и не занимает место
- Оба поля редактируются через popup «...» рядом с названием доски

Каждая доска имеет собственный набор групп, задач и WIP-лимитов. Все доски хранятся в одном `data.json`.

### Раскладка доски

Пользователь видит доску с группами, расположенными в виде сетки:

```
┌─────────────────────────────────────────────┐
│  ▶ Бэклог (12)                    свёрнут  │
│─────────────────────────────────────────────│
│  ┌───────────────┐   ┌───────────────┐      │
│  │    Фокус      │   │   В работе    │      │
│  │               │   │               │      │
│  └───────────────┘   └───────────────┘      │
│  ┌──────────────────────────────────────┐   │
│  │       Орг. намерения                 │   │
│  │                                      │   │
│  └──────────────────────────────────────┘   │
│  ┌──────────────────────────────────────┐   │
│  │       Делегировано                   │   │
│  │                                      │   │
│  └──────────────────────────────────────┘   │
│─────────────────────────────────────────────│
│  ▶ Завершённые (47)               свёрнут  │
└─────────────────────────────────────────────┘
```

- **Бэклог** — сворачиваемая панель сверху, по умолчанию свёрнута
- **Строка 1:** две группы рядом — «Фокус» (слева) и «В работе» (справа)
- **Строка 2:** «Орг. намерения» — занимает всю ширину
- **Строка 3:** «Делегировано» — занимает всю ширину
- **Завершённые** — сворачиваемая панель снизу, по умолчанию свёрнута

Скрытые группы не занимают место в раскладке — доска перестраивается автоматически. Ширина групп задаётся в настройках доски.

Внутри каждой группы — карточки задач.

**Компактный вид карточки на доске:**

```
┌─────────────────────────┐
│ 🔴 ⏳       2026-03-24 │
│ Подготовить отчёт для   │
│ совета директоров       │
│ 👤 Иванов А.            │
└─────────────────────────┘
```

Карточка отображает:

- **Что** — описание задачи (основной текст)
- **Кто** — исполнитель
- **Когда** — дедлайн
- **Приоритет** — иконка: 🔴 высокий / 🟡 средний / 🟢 низкий
- **Статус** — иконка: 📋 новая / 🛠️ в работе / ⏳ ожидает / ✅ завершена
- **Пост-задачи** — маркер `↪ N` с числом незаведённых пунктов (только если они есть)

Приоритет и статус отображаются компактно через иконки, не занимая место текстом. Остальные поля (Зачем, Создана) доступны при открытии карточки в модальном окне редактирования.

**Взаимодействие:**

- Нажатие кнопки "+" в группе — создание новой задачи
- Клик по карточке — открытие модального окна редактирования
- Drag-and-drop карточки — перемещение между группами
- Кнопка удаления на карточке или в модальном окне

### Первый запуск

При первом открытии плагина пользователь видит доску с дефолтным названием (например, «Моя доска») и пустые группы с текстами-подсказками (см. «Пустое состояние»). Этого достаточно, чтобы сразу начать добавлять задачи.

### Пустое состояние (Empty State)

Когда группа не содержит задач, в ней отображается текст-подсказка:

| Группа | Текст подсказки |
|--------|----------------|
| **Фокус** | «Что сейчас требует вашего внимания? Перетащите сюда задачи, которые нельзя упускать из виду» |
| **В работе** | «Чем вы занимаетесь прямо сейчас? Добавьте задачи, над которыми работаете лично» |
| **Орг. намерения** | «Что запланировано на эту неделю? Разместите здесь цели, которые хотите закрыть до конца недели» |
| **Делегировано** | «Что вы поручили другим? Добавьте задачи, переданные коллегам, чтобы не забыть проверить их статус» |
| **Бэклог** | «Задачи на будущее. Складывайте сюда всё, что появляется на горизонте, но пока не готово к работе» |
| **Завершённые** | «Пока пусто — завершённые задачи будут появляться здесь» |

## Анализ конкурентов

### Плагины Obsidian

| Плагин | Что умеет | Чего не хватает |
|--------|-----------|-----------------|
| **Kanban** (mgmeyers) | Kanban-доска, drag-and-drop, произвольные колонки | Карточки — простой текст, нет структурированных полей SMART, нет фиксированной методологии |
| **CardBoard** (roovo) | Теги как колонки, отображение подзадач, синхронизация с markdown | Нет структурированных полей на карточках, требует ручной настройки тегов |
| **Task Board** (tu2-atmanand) | Сканирование vault, визуальная доска, приоритеты, дедлайны | GTD-ориентирован (Inbox/Next/Waiting/Someday), не SMART-стиль |
| **Tasks** (obsidian-tasks-group) | Мощные запросы, кастомные статусы, группировка | Только списки, нет визуальной доски |
| **Projects** | Board/table/calendar виды, frontmatter-поля | Требует ручной настройки структуры, не опционирован |
| **TaskNotes** (callumalpass) | Задачи как файлы с YAML, kanban через Bases | Нет встроенной схемы — пользователь сам определяет поля |

### Внешние инструменты

| Инструмент | Плюсы | Минусы |
|------------|-------|--------|
| **Trello** | Карточки с кастомными полями, метки, чек-листы | Облачный, нет интеграции с заметками, не local-first |
| **Notion** | Базы данных, шаблоны карточек, kanban-вид | Облачный, не markdown, не Obsidian |
| **ClickUp** | 15+ видов, кастомные поля, OKR, трекинг нагрузки | Тяжёлый SaaS, избыточен для личного управления задачами |
| **Monday.com** | Визуальные доски, автоматизации, дашборды | Облачный, корпоративный, дорогой |

### Ключевой вывод

Ни один существующий плагин Obsidian не предлагает из коробки комбинацию:
1. Четырёх конкретных групп задач (Фокус / В работе / Орг. намерения / Делегировано)
2. Структурированных карточек SMART (Что / Зачем / Кто / Когда / Статус)
3. Визуальной доски с drag-and-drop

Ближайшие подходы требуют сборки из 2-3 плагинов (Tasks + Kanban + шаблоны) или использования облачных SaaS-решений (Notion, ClickUp).

**TaskMaster занимает свободную нишу** — опционированный, local-first инструмент для проектного менеджера внутри Obsidian.

## Техническое окружение

- **Платформа:** плагин для Obsidian (community plugin)
- **Язык:** TypeScript
- **Хранение данных:** JSON через стандартный Obsidian API (`loadData()` / `saveData()`), файл `.obsidian/plugins/taskmaster/data.json`
- **UI-фреймворк:** Svelte

**Подготовка к мобильной адаптации (закладывается на MVP):**

- CSS через относительные единицы (`rem`, `%`, `fr`) вместо жёстких `px`
- Layout на CSS Grid — позволит адаптировать раскладку одним media query
- Drag-and-drop через библиотеку с touch-поддержкой (например, `SortableJS` или `dnd-kit`)
- Кнопки и действия (удаление, меню «...») всегда видны — не прятать за hover-эффектами

## Пост-MVP фичи

Функции, запланированные на будущие версии:

- **Быстрая автосортировка** — разовая сортировка карточек внутри группы по дедлайну, статусу или дате создания
- **Поиск и фильтрация** — поиск задач по тексту, фильтрация по исполнителю, статусу, просроченным
- **Автодополнение поля «Кто»** — справочник исполнителей с подсказками при вводе
- **Мобильная адаптация** — адаптивная раскладка для узких экранов (группы в одну колонку)
