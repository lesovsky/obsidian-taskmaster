# Task 05: Title resolution

## Required Skills

Перед выполнением задачи загрузи:
- `/skill:code-writing` — [skills/code-writing/SKILL.md](~/.claude/skills/code-writing/SKILL.md)

## Description

Фича даёт пользователю возможность переименовать группу на доске. Пустое сохранённое название
означает «использовать дефолтное локализованное имя» — это же и механизм сброса (Decision 4
tech-spec). Правило отката одно и то же во всех местах, где название группы **показывается**
(поле редактирования в попапе настроек доски местом отображения не является — см. ниже).

Задача — реализовать это правило один раз, отдельным чистым модулем `src/ui/groupTitle.ts`,
и покрыть его unit-тестами.

Зачем отдельный модуль, а не инлайн в компонентах:
- Testing Strategy требует unit-покрытия правил отката, но `vitest.config.ts` задаёт
  `environment: 'node'`, DOM-библиотеки в проекте нет — логика внутри `.svelte` не тестируется
  вообще.
- Мест вызова три, и все они на доске (задача 06): заголовок обычной группы
  (`GroupHeader`), заголовок свёрнутой группы (`CollapsibleGroup`), заголовок попапа настроек
  группы (`GroupSettingsPopup`). Три копии одного условия — три места для расхождения.
  `EmptyState` потребителем НЕ является: он отображает подсказку, а не название группы, и
  решает между исходной и нейтральной подсказкой по самому сохранённому названию. Второй
  экспорт под него заводить не нужно — задача 06 это прямо запрещает.

**Поле ввода названия в попапе настроек доски (задача 08) резолвер НЕ использует** и
потребителем этого модуля не является. Его значение — сырое сохранённое название (пустое,
если группу не переименовывали), а дефолтная локализованная подпись идёт в `placeholder`.
Причина (tech-spec Decision 4, абзац «The editing field is not a display site and must not use
the helper»): если пропустить поле через резолвер, у непереименованной группы в нём окажется
дефолтное название как обычный текст — placeholder не покажется никогда, а «Сохранить» без
единой правки запишет дефолты явными пользовательскими названиями всем шести группам. После
этого заголовки перестанут переводиться при смене языка, а пустые группы переключатся на
нейтральную подсказку.

**Критично по сигнатуре:** функция принимает **простые строки** — сохранённое название и
дефолтную подпись, — а НЕ объект `Group`. Поле `Group.title` добавляется задачей 03 в той же
волне; зависимость от типа связала бы две параллельные задачи, а рассинхрон всплыл бы только
волной позже, потому что unit-тесты типы не проверяют (`vitest` гоняет TS через esbuild,
без type-check).

Задача не занимается нормализацией хранимого значения (trim, лимит 40 символов) — это
Decision 7 и зона задач 03 (загрузка) и 08 (сохранение). Здесь только резолв отображаемого
значения.

## What to do

- Создать новый модуль `src/ui/groupTitle.ts` с одной экспортируемой чистой функцией резолва
  отображаемого названия группы. Аргументы — сохранённое название и дефолтная локализованная
  подпись, обе `string`. Возврат — `string`.
- Правило: если сохранённое название после обрезки краевых пробелов непустое — вернуть
  сохранённое название; иначе вернуть дефолтную подпись.
- Никаких импортов из `svelte`, `src/i18n`, `src/data/types` и никакого обращения к стору:
  модуль должен оставаться чистым и запускаться в `node`-окружении без моков. Дефолтная подпись
  приходит параметром — её добывает вызывающая сторона (из `$groupLabels`).
- Написать `tests/unit/groupTitle.test.ts` — сначала тесты, потом реализацию (см. TDD Anchor).
- Не трогать компоненты: подключение вызовов — задача 06.

## TDD Anchor

Тесты пишем ДО реализации: пишем → запускаем → убеждаемся что падают → пишем код →
убеждаемся что проходят.

- `tests/unit/groupTitle.test.ts::пустое название → дефолтная подпись` — сохранённое название
  `''`, возвращается переданная дефолтная подпись.
- `tests/unit/groupTitle.test.ts::название из одних пробелов → дефолтная подпись` — `'   '`
  (а также вариант с табом/переводом строки) равносилен пустому.
- `tests/unit/groupTitle.test.ts::непустое название побеждает` — сохранённое `'Мои задачи'`
  возвращается вместо дефолтной подписи.
- `tests/unit/groupTitle.test.ts::название с краевыми пробелами вокруг текста непустое` —
  `'  Мои задачи  '` считается непустым и возвращается (значение не подменяется дефолтом).
- `tests/unit/groupTitle.test.ts::дефолтная подпись возвращается как есть` — резолв не
  модифицирует дефолт (проверяется на дефолте с не-ASCII символами / другой локали).

## Details

**Files:**
- `src/ui/groupTitle.ts` — **новый файл.** Один экспорт: чистая функция резолва
  (предлагаемое имя `resolveGroupTitle(storedTitle: string, defaultLabel: string): string`).
  Тело — одно условие. Никакого состояния, никаких побочных эффектов.
- `tests/unit/groupTitle.test.ts` — **новый файл.** `describe` на имя функции, по одному `it`
  на случай из TDD Anchor. Импорт: `import { describe, it, expect } from 'vitest'` и
  `from '../../src/ui/groupTitle'`.

**Dependencies:**
- Зависит от Task 1 (волна 1): пин Node `^22.12.0 || >=24.0.0` и работоспособность `npm test`. Без этого
  vitest не запустится и задачу нельзя верифицировать.
- **Не** зависит от Task 3 (`Group.title`) — намеренно, см. Decision 4. Обе идут в волне 2
  параллельно.
- Единственный потребитель — Task 6: три места отображения названия на доске. В этой задаче их не
  трогаем.
- Task 8 (попап настроек доски) потребителем **не** является: поле ввода названия резолвер не
  вызывает (Decision 4). Задача 08 читает этот модуль только для контекста.
- Новых npm-пакетов нет.

**Edge cases:**
- Сохранённое название `''` → дефолтная подпись.
- Сохранённое название из одних пробельных символов (пробелы, табы, перевод строки) →
  дефолтная подпись. Проверка пустоты — по обрезанному значению.
- Название с текстом и краевыми пробелами → считается непустым.
- Оба аргумента пустые → вернётся пустая строка. Это не отдельная ветка: дефолтная подпись
  всегда приходит из `groupLabels` и пустой не бывает; специальную обработку не добавляем.

**Implementation hints:**
- Пустоту определяем по `trim()`, но **возвращаем сохранённое значение как есть**, не
  обрезанное. Нормализация (trim + лимит 40 символов) — обязанность стора и загрузчика
  (Decision 7), дублировать её здесь значит размазать ответственность и создать второе место,
  где правило может разойтись. Функция резолвит, а не нормализует.
- Не добавлять рантайм-защиту от `undefined`/`null`/не-строки. Строгий TS даёт типовую
  гарантию, а данные нормализуются на загрузке (Decision 7). CLAUDE.md: минимум кода,
  ничего спекулятивного.
- Не добавлять второй экспорт «на будущее» (варианты с объектом группы, мемоизацию,
  дефолт-параметры) — YAGNI, ревьюеры это отметят.
- Комментарии/JSDoc — только если поясняют неочевидное (например, почему аргумент строка,
  а не `Group`). Одну такую строку оставить полезно: она объясняет решение следующему читателю.
- Проверка `groupTitle` как имени файла: в `src/ui/` уже лежат `boardLayoutUtils.ts` и
  `useSortable.ts` — camelCase для `.ts`-утилит, PascalCase только для `.svelte`. Имя из
  tech-spec (`groupTitle.ts`) конвенции соответствует, менять его нельзя: на этот путь
  ссылаются задача 06 (вызывает) и задача 08 (читает для контекста).
- Не закладывать отдельного поведения под поле ввода в попапе настроек доски: контракт уже
  зафиксирован (Decision 4) — поле показывает сырое сохранённое значение, дефолт идёт в
  `placeholder`, резолвер там не вызывается. Никакого «режима для формы», флага или второго
  варианта возврата в этом модуле быть не должно.
