# User Spec: Пост-задачи

## Что делаем

У каждой задачи появляется список **пост-задач** — коротких пунктов о том, что нужно сделать после её выполнения («Провести ретро» после «Выпустить релиз»). Список редактируется в форме задачи, а на карточке виден маркер `↪ N` с числом ещё не заведённых пунктов. Когда задача попадает в группу «Завершённые», все её незаведённые пункты автоматически превращаются в настоящие задачи в бэклоге той же доски, и пользователь видит об этом уведомление. Любой пункт можно завести в бэклог и раньше — кнопкой в форме.

Связей между карточками (ссылок по идентификатору, как в трекерах) нет: пункт — это текст внутри задачи, а заведённая из него задача — обычная самостоятельная карточка.

## Зачем

Сейчас у пост-задачи два плохих варианта. Завести её отдельной карточкой заранее — значит захламить доску задачей, которую ещё рано делать. Записать её в «Зачем» основной задачи — значит забыть о ней: основная задача закрывается, уезжает в «Завершённые» (группа по умолчанию свёрнута) и через 30 дней удаляется автоочисткой вместе с заметкой. На доске никакого сигнала, что что-то осталось несделанным, нет.

Пример автора плагина: задача «Выпустить релиз» с дедлайном. После релиза нужно провести ретро, но заводить карточку «Ретро» сейчас бессмысленно — до релиза её не сделать. С фичей пункт «Провести ретро» живёт внутри задачи о релизе, маркер на карточке напоминает о нём, а в момент закрытия релиза карточка «Провести ретро» сама появляется в бэклоге.

## Пользовательские истории

- Как проектный менеджер, я хочу записать в задачу, что нужно сделать после неё, чтобы не заводить преждевременные карточки и не держать это в голове.
- Как проектный менеджер, я хочу видеть на доске, у каких задач есть несделанные пост-задачи, чтобы помнить о них, не открывая каждую карточку.
- Как проектный менеджер, я хочу, чтобы при закрытии задачи её пост-задачи сами появлялись в бэклоге, чтобы физически не забыть о них.
- Как проектный менеджер, я хочу завести пост-задачу в бэклог раньше, не дожидаясь закрытия основной, чтобы начать её, когда она стала актуальной.
- Как проектный менеджер, я хочу отменить случайное завершение и получить доску в прежнем виде, без лишних карточек в бэклоге.

### Пользовательские сценарии

**Сценарий 1: Добавление пост-задач**
1. Пользователь открывает карточку «Выпустить релиз».
2. В форме под полем «Зачем» видит блок «После выполнения» с кнопкой «+ Добавить пункт».
3. Нажимает кнопку, вводит «Провести ретро», нажимает Enter — появляется поле для следующего пункта, в него вводит «Разослать release notes».
4. Нажимает «Сохранить».
5. Результат: на карточке в верхней строке рядом с дедлайном появляется `↪ 2`. При наведении на маркер показывается список обоих пунктов.

**Сценарий 2: Автозаведение при завершении**
1. Релиз выпущен, пользователь нажимает ☑ на карточке «Выпустить релиз».
2. Карточка переезжает в «Завершённые», появляется обычный toast завершения с кнопкой «Отменить».
3. В конце бэклога этой доски появляются две задачи: «Провести ретро» и «Разослать release notes». У каждой в «Зачем» записано «После: Выпустить релиз», статус «Новая», приоритет — по умолчанию из настроек.
4. Появляется уведомление Obsidian: «Заведено задач в «Бэклог»: 2».
5. Результат: пост-задачи на доске, забыть о них нельзя. В форме завершённой задачи оба пункта отмечены «✓ заведено», маркера на её карточке нет.

То же происходит, если перетащить карточку в «Завершённые» мышью (без toast'а отмены — у перетаскивания его нет и сейчас).

**Сценарий 3: Отмена случайного завершения**
1. Пользователь по ошибке нажал ☑ на задаче с двумя незаведёнными пунктами.
2. Задача ушла в «Завершённые», в бэклоге появились две задачи, показано уведомление.
3. В течение 7 секунд пользователь нажимает «Отменить» в toast'е.
4. Результат: задача вернулась на прежнее место с прежним статусом, две автозаведённые задачи удалены из бэклога, оба пункта снова в состоянии «не заведено», маркер `↪ 2` вернулся на карточку.

**Сценарий 4: Досрочное заведение пункта**
1. До релиза стало понятно, что release notes нужно готовить уже сейчас.
2. Пользователь открывает «Выпустить релиз», у пункта «Разослать release notes» нажимает «→ в бэклог». Пункт подсвечивается как «будет заведён при сохранении».
3. Нажимает «Сохранить».
4. Результат: в конце бэклога появляется задача «Разослать release notes» («Зачем»: «После: Выпустить релиз»), показано уведомление «Заведено задач в «Бэклог»: 1». Пункт в форме помечен «✓ заведено», маркер на карточке показывает `↪ 1`. При последующем завершении релиза будет заведено только «Провести ретро».

**Сценарий 5: Передумал в форме**
1. Пользователь нажимает «→ в бэклог» у пункта, затем закрывает форму через Escape.
2. Результат: ничего не создано, пункт остался незаведённым, прочие несохранённые правки формы тоже отброшены.

## Дизайн и интерфейс

### Страницы / экраны
- **Модальное окно задачи (создание и редактирование):** новый блок «После выполнения» между полем «Зачем» и строкой «Кто / Когда».
- **Доска:** маркер на карточке задачи в обоих режимах отображения; уведомление Obsidian при заведении задач.

### Ключевые компоненты
- **Блок «После выполнения» в форме:**
  ```
  После выполнения
  [ Провести ретро              ] [→ в бэклог] [✕]
  [ Разослать release notes     ] [→ в бэклог] [✕]
  ✓ Обновить roadmap — заведено                [✕]
  [+ Добавить пункт]
  ```
  - Незаведённый пункт — однострочное поле ввода, кнопка «→ в бэклог» и кнопка удаления ✕.
  - «→ в бэклог» — переключатель: первое нажатие помечает пункт «будет заведён при сохранении» (пункт визуально подсвечен, кнопка в нажатом состоянии), повторное снимает пометку.
  - Заведённый пункт — серый текст с меткой «✓ заведено», не редактируется, кнопки «→ в бэклог» нет, удалить можно (удаление касается только записи в списке, созданная задача остаётся на доске).
  - Если пунктов нет — видна только кнопка «+ Добавить пункт».
  - При достижении лимита в 20 пунктов кнопка «+ Добавить пункт» недоступна.
  - **У задачи, которая лежит в группе «Завершённые», блок только для чтения:** пункты показываются без полей ввода и без кнопок «→ в бэклог», ✕ и «+ Добавить пункт». Если пунктов нет, блок не показывается. Понадобилась пост-задача к уже закрытой задаче — пользователь заводит обычную новую карточку.
- **Маркер на карточке:**
  - Обычный режим: `↪ N` в верхней строке, слева от дедлайна. Если дедлайна нет — маркер стоит там, где был бы дедлайн (справа в строке).
  - Компактный режим: `↪N` непосредственно перед дедлайном (или на его месте, если дедлайна нет).
  - N — число незаведённых пунктов. Если N = 0 (пунктов нет или все заведены) — маркера нет.
  - При наведении — всплывающая подсказка со списком текстов незаведённых пунктов, каждый с новой строки.
  - Маркер не кликабелен: клик по нему работает как клик по карточке (открывает форму), перетаскивание карточки за маркер работает как за любое другое место.
- **Уведомление:** стандартное уведомление Obsidian (всплывает в правом верхнем углу и исчезает само). Текст: «Заведено задач в «{название бэклога}»: N». Название бэклога — текущее отображаемое название группы на доске (с учётом переименования из фичи 0011). Если бэклог на этой доске скрыт, к тексту добавляется «(группа скрыта)».

### Формы и ввод данных
- **Форма задачи, блок «После выполнения»:** поля — текст пункта; валидация — до 200 символов на пункт (`maxlength`), до 20 пунктов на задачу; пункты из одних пробелов и пустые при сохранении отбрасываются, текст обрезается по краям; действия — «+ Добавить пункт», Enter в поле пункта (добавляет новый пустой пункт после текущего и ставит в него фокус; если лимит достигнут — ничего не делает), «→ в бэклог», ✕. Всё применяется только по «Сохранить»; Escape и закрытие окна отбрасывают изменения списка, как и остальных полей.

### UX-поведение
- Порядок пунктов задаёт сам пользователь при вводе: «+ Добавить пункт» добавляет пункт в конец списка, Enter — сразу после текущего. Перестановки уже введённых пунктов нет.
- Задачи из пунктов создаются в том порядке, в котором пункты стоят в списке, и добавляются в конец бэклога.
- Уведомление показывается один раз на одно действие (одно сохранение формы или одно завершение), с общим числом заведённых задач. Если заводить нечего — уведомления нет.
- Бэклог при заведении задач не разворачивается автоматически (как и «Завершённые» при быстром завершении).
- Все новые тексты — на английском и русском.

## Как должно работать

### Основной сценарий
1. Пользователь записывает пост-задачи в форме задачи и сохраняет.
2. На карточке появляется маркер `↪ N`.
3. Пользователь завершает задачу — кнопкой ☑ или перетаскиванием в «Завершённые».
4. Каждый незаведённый пункт становится новой задачей в конце бэклога той же доски: «Что» — текст пункта; «Зачем» — «После: » + «Что» родительской задачи (префикс — на языке интерфейса в момент создания, «After: » для английского; дальше это обычный текст и при смене языка не переводится); «Кто» и «Когда» — пусто; приоритет — по умолчанию из настроек плагина; статус — «Новая»; дата создания — сегодня.
5. Пункты помечаются «✓ заведено», маркер исчезает, показывается уведомление с числом заведённых задач.

### Что считается завершением
- **Считается:** попадание задачи в группу «Завершённые» из любой другой группы — кнопкой ☑ или перетаскиванием.
- **Не считается:** перестановка задачи внутри «Завершённых»; выбор статуса «Завершена» в форме (задача при этом остаётся в своей группе, как и сейчас). Если такую задачу позже перетащить в «Завершённые», пункты заведутся в этот момент.

### Граничные случаи
- **Отмена быстрого завершения (☑ → «Отменить»):** автозаведённые этим завершением задачи удаляются с доски, их пункты возвращаются в состояние «не заведено». Пункты, заведённые раньше (досрочно из формы), не затрагиваются. Автозаведённая задача удаляется, даже если за эти 7 секунд её успели изменить или перетащить в другую группу доски; если её уже удалили — она просто пропускается. Список пунктов родителя за эти 7 секунд измениться не может: родитель лежит в «Завершённых», где список только для чтения.
- **Перетаскивание в «Завершённые»:** отмены нет — как и сейчас. Если после этого вытащить задачу обратно и снова завершить, повторно ничего не создаётся: все пункты уже помечены «заведено».
- **Задача уже в «Завершённых»:** список пост-задач у неё не редактируется (см. «Ключевые компоненты»), поэтому незаведённый пункт, который никогда не заведётся и исчезнет при автоочистке, появиться не может. Задача, закрытая только статусом в форме, лежит в своей рабочей группе — её список редактируется как обычно.
- **Задача без пунктов или со всеми заведёнными пунктами** завершается ровно как сейчас: ничего не создаётся, уведомления нет.
- **Удаление задачи с незаведёнными пунктами:** пункты пропадают вместе с задачей. Отдельного предупреждения нет; действует обычная отмена удаления в течение 7 секунд.
- **Бэклог скрыт на доске:** задачи всё равно создаются в бэклоге, уведомление сообщает, что группа скрыта.
- **Бэклог переименован:** в уведомлении используется его текущее название.
- **Длинный текст родительской задачи:** «Зачем» новой задачи обрезается до лимита поля «Зачем» (10 000 символов).
- **Досрочное заведение в новой задаче:** в форме создания тоже можно отметить пункт «→ в бэклог»; задача-пункт создаётся при сохранении вместе с самой новой задачей.
- **Пункт отмечен «→ в бэклог», но текст стёрт до пустого:** пункт отбрасывается при сохранении, задача не создаётся.
- **Существующие задачи после обновления плагина:** получают пустой список пост-задач, выглядят и ведут себя как раньше.
- **Повреждённые данные** (список пост-задач испорчен ручной правкой `data.json` или неудачной синхронизацией): при загрузке приводится к валидному виду — не-список становится пустым списком, некорректные элементы отбрасываются, лишние сверх 20 и символы сверх 200 обрезаются. Плагин при этом запускается и показывает доску.
- **Автоочистка завершённых:** завершённая задача удаляется по сроку хранения как обычно. Её незаведённых пунктов к этому моменту уже нет — они заведены в момент завершения (исключение — задача, закрытая статусом в форме: она не попадает в «Завершённые» и автоочисткой не удаляется).

## Критерии приёмки

- [ ] AC-1. В форме задачи (создание и редактирование) есть блок «После выполнения»: пункты добавляются кнопкой и клавишей Enter, удаляются ✕, сохраняются по «Сохранить» и восстанавливаются после перезапуска Obsidian; Escape отбрасывает изменения списка.
- [ ] AC-2. Пустые и состоящие из пробелов пункты не сохраняются; поле пункта не принимает больше 200 символов; добавить больше 20 пунктов нельзя.
- [ ] AC-3. На карточке с незаведёнными пунктами виден маркер `↪ N` с их числом — в обычном и компактном режимах, с дедлайном и без него; подсказка при наведении перечисляет тексты незаведённых пунктов; при N = 0 маркера нет.
- [ ] AC-4. Завершение кнопкой ☑ задачи с незаведёнными пунктами создаёт по задаче на каждый такой пункт в конце бэклога той же доски, с полями по правилу из «Основного сценария»; пункты помечаются «✓ заведено»; показывается одно уведомление с числом заведённых задач.
- [ ] AC-5. Перетаскивание такой задачи в «Завершённые» из другой группы даёт тот же результат, что AC-4. Перестановка внутри «Завершённых» ничего не создаёт.
- [ ] AC-6. Выбор статуса «Завершена» в форме ничего не создаёт.
- [ ] AC-7. «Отменить» в toast'е быстрого завершения удаляет задачи, автозаведённые этим завершением, и возвращает их пункты в состояние «не заведено»; досрочно заведённые пункты остаются заведёнными.
- [ ] AC-8. Повторное завершение задачи (вытащили из «Завершённых» и закрыли снова) не создаёт дублей.
- [ ] AC-9. «→ в бэклог» в форме только помечает пункт; задача создаётся по «Сохранить», с уведомлением; Escape после пометки ничего не создаёт.
- [ ] AC-10. Если бэклог скрыт, задачи создаются в нём, а уведомление сообщает, что группа скрыта; в уведомлении используется текущее (возможно переименованное) название бэклога.
- [ ] AC-11. После обновления с текущей версии данных существующие задачи получают пустой список пост-задач, доска выглядит как до обновления; повреждённый список пост-задач в `data.json` не мешает запуску плагина.
- [ ] AC-12. В форме задачи из группы «Завершённые» блок «После выполнения» только для чтения: нельзя добавить, изменить, удалить пункт или пометить его «→ в бэклог»; при пустом списке блок не показывается.
- [ ] AC-13. Все новые тексты интерфейса и уведомления есть на английском и русском.

## Ограничения

- Хранение — только в существующем `data.json`, внутри объекта задачи. Пункты не хранятся отдельными записями задач: такие записи удалила бы очистка «осиротевших» задач.
- Изменение схемы данных требует миграции (текущая версия данных — 8, новая — 9) и санитизации нового поля на каждой загрузке — по принятому в проекте правилу (решение из фичи 0011).
- Уведомление использует стандартный механизм уведомлений Obsidian; тестовый стенд должен его поддерживать.
- Стили — только в `src/styles.css`, классы с префиксом `tm-`, цвета через переменные Obsidian; проверка в светлой и тёмной темах.
- Никакой вставки пользовательского текста как разметки — только экранируемый вывод.
- Мобильная платформа не является целевой.

## Риски

- **Риск:** в компактном и особенно в мультиколоночном режиме (4 колонки) места в строке карточки почти нет; маркер отнимет ширину у текста задачи. **Митигация:** маркер — короткий (`↪N`, без пробела в компактном режиме), фиксированной ширины и показывается только при N > 0; текст задачи, как и сейчас, сжимается с многоточием и остаётся доступен в подсказке при наведении. Отдельного запасного режима (скрывать маркер в узких колонках) не делаем — сознательно: скрытый маркер лишил бы фичу смысла там, где задач больше всего. Проверка отображения в мультиколоночном режиме входит в ручную проверку.
- **Риск:** при отмене быстрого завершения можно удалить не те задачи или не вернуть пункты. **Митигация:** отмена трогает только задачи, созданные именно этим завершением; покрывается юнит- и e2e-тестами (AC-7).
- **Риск:** перестановка внутри «Завершённых» ошибочно запускает автозаведение (сейчас она уже переставляет дату завершения). **Митигация:** явное правило «только из другой группы», отдельный тест (AC-5).
- **Риск:** правки списка в форме утекают в сохранённые данные без «Сохранить» (форма получает живой объект задачи). **Митигация:** форма работает с копией списка; тест на Escape (AC-1, AC-9).
- **Риск:** автозаведение создаёт в бэклоге неактуальные задачи. **Митигация:** принято сознательно — удалить лишнюю карточку проще, чем вспомнить забытую; неактуальный пункт можно удалить из списка до закрытия.

## Технические решения

- Мы решили хранить пост-задачи списком текстовых пунктов внутри задачи, потому что пользователю нужен не граф связей, а напоминание с конкретным содержанием, и маркер должен знать, сколько пунктов ещё не заведено.
- Мы решили не делать связи между карточками по идентификатору, потому что это избыточно для задачи «не забыть».
- Мы решили не ограничиваться флагом «есть пост-задачи», потому что флаг не говорит, что именно нужно сделать, и не может погаснуть сам.
- Мы решили не использовать для этого поле «Зачем», потому что по свободному тексту нельзя понять, остались ли незаведённые пункты, — маркеру нечего считать.
- Мы решили заводить пункты автоматически при завершении, а не только показывать маркер, потому что завершённая задача уезжает в свёрнутую группу и через 30 дней удаляется — маркер там никто не увидит. Уведомление-напоминание без создания задач и окно с галочками при завершении отвергнуты: первое легко проигнорировать, второе добавляет шаг к каждому закрытию.
- Мы решили считать завершением только попадание в «Завершённые», а не смену статуса в форме, потому что смена статуса в форме сейчас не перемещает задачу и не должна менять своё поведение.
- Мы решили создавать задачи по кнопке «→ в бэклог» только при сохранении формы, потому что тогда у формы один момент сохранения и Escape честно отменяет всё.
- Мы решили сделать список пост-задач у задач в «Завершённых» только для чтения, а не заводить добавленные туда пункты сразу, потому что кейс редкий, обычная новая карточка решает его тем же числом действий, а запрет проще реализовать и поддерживать.
- Мы решили оставлять заведённые пункты в списке с отметкой «✓ заведено», потому что это история происхождения задач и защита от повторного заведения.

## Тестирование

**Unit-тесты:** делаются всегда, не обсуждаются. Покрывают: логику автозаведения (какие пункты заводятся, поля новых задач, обрезка «Зачем»), отмену быстрого завершения с откатом автозаведённых задач, отсутствие повторного заведения, правило «перестановка внутри Завершённых не считается», миграцию данных на версию 9, санитизацию повреждённого списка.

**Интеграционные тесты:** не делаем — у плагина нет внешних сервисов; взаимодействие стора и интерфейса покрывается e2e.

**E2E тесты:** делаем — в проекте есть Playwright-стенд, а ключевое поведение фичи (форма, маркер в двух режимах, ☑ с отменой, перетаскивание, уведомление) проверяется только в интерфейсе. Отдельный файл сценариев для фичи; существующие e2e-тесты должны оставаться зелёными.
