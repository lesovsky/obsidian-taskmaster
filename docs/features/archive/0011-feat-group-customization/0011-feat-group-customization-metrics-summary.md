## Что стоит помнить при планировании следующей фичи

Маршрут «полная пользовательская спецификация → автопилот с мультивалидацией» оказался
несоразмерен объёму: код фичи — примерно на два вечера, а процесс занял 68 отчётов проверяющих.
Окупились четыре находки: контракт поля ввода (испортил бы данные пользователя), метод из
неподдерживаемого стандарта в сборке, два непокрытых места вывода, коллизия тестовых атрибутов.
Не окупились: мутационные прогоны в каждой задаче, три раунда ревью на трёхстрочных диффах,
повторная валидация уже проверенного.

Для фич такого размера разумнее: сразу техническая спецификация и написание кода по задачам,
один проверяющий на задачу, без пользовательской спецификации с тремя раундами.
