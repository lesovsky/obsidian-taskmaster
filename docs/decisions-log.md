# Architecture Decision Log

Cross-feature log of key architectural decisions. Updated after each feature is finalized.
Used by tech-spec planning and code research to avoid repeating mistakes and re-litigating settled choices.

## [0011-feat-group-customization] Порядок групп через CSS, без перестановки разметки

**Date:** 2026-08-11
**Feature:** [0011-feat-group-customization]
**Status:** Accepted

**Context:** Порядок групп на доске стал настраиваемым. Очевидная реализация — свернуть шесть
литеральных блоков разметки в цикл по настроенному порядку.

**Decision:** Порядок задаётся CSS-свойством `order` на существующих обёртках. Шесть блоков
остаются литеральными и на своих местах в разметке; меняется только стиль обёртки. Функция
раскладки половинок получает предварительно отсортированный массив и сама не меняется.

**Rationale:** Цикл пересоздал бы элементы-обёртки и уничтожил привязанные к ним инстансы
SortableJS — перетаскивание задач названо в CLAUDE.md критической функциональностью. Гипотеза
проверялась эмпирически в Chromium на воспроизведении реальной сетки ДО написания кода: порядок
соблюдается, пары половинок собираются в строку даже когда разнесены в разметке, `grid-column`
ведёт себя корректно.

**Consequences:** Разметка доски остаётся «плоской» и не масштабируется на динамический набор
групп — если когда-нибудь понадобятся пользовательские группы, это решение придётся пересматривать
целиком. Секция заметок обязана иметь явное значение `order`: элемент без него получает `0` и
уезжает наверх. Проверки порядка в сценариях не могут опираться на индекс элемента — DOM-порядок
не меняется вовсе, проверять нужно вычисленные значения и геометрию.

**Tech debt introduced:** Порядок обхода с клавиатуры и чтения экранными читалками следует
разметке и расходится с визуальным. Принято сознательно: выравнивание потребовало бы перестановки
разметки, то есть возврата исходного риска.

## [0011-feat-group-customization] Три раздельных тестовых атрибута вместо одного

**Date:** 2026-08-11
**Feature:** [0011-feat-group-customization]
**Status:** Accepted

**Context:** Названия групп стали редактируемыми, поэтому сценарии больше не могут находить группы
по тексту. Нужен устойчивый признак — и напрашивалось переиспользовать уже существующий.

**Decision:** Три различных атрибута: на теле группы (существовал), на внешней обёртке группы на
доске и на строке группы в попапе настроек.

**Rationale:** Общий атрибут дал бы по два совпадения на группу. Двенадцать проверок упали бы
громко, а три места — молча: обращения в сценариях колонок карточек вернули бы обёртку вместо тела
и прочитали пустое свойство, а вспомогательная функция раскрытия группы глотает ошибку в `catch` и
просто перестала бы разворачивать. Попап и доска находятся в разметке одновременно, поэтому их
признаки тоже обязаны различаться.

**Consequences:** При добавлении новых проверок нужно осознанно выбирать уровень: тело группы —
для содержимого и стилевых свойств, обёртка — для позиции и раскладки, строка попапа — для
настроек. Обёртка существует всегда, тело сворачиваемой группы отсутствует в разметке, пока группа
свёрнута.

**Tech debt introduced:** None

## [0011-feat-group-customization] Поле ввода названия не является местом отображения

**Date:** 2026-08-11
**Feature:** [0011-feat-group-customization]
**Status:** Accepted

**Context:** Название группы разрешается из сохранённого значения и локализованного дефолта общей
чистой функцией. Первая редакция спецификации предписывала использовать её и для поля ввода в
настройках.

**Decision:** Поле ввода получает сырое сохранённое название, которое может быть пустым.
Локализованный дефолт идёт только в подсказку ввода. Функция разрешения используется исключительно
в местах отображения.

**Rationale:** Иначе у непереименованной группы в поле лежал бы дефолт как обычный текст: подсказка
не показалась бы никогда, а нажатие «Сохранить» без единой правки записало бы дефолтные названия
явными значениями всем шести группам. Доска потеряла бы перевод заголовков при смене языка, а пустые
группы переключились бы на нейтральную подсказку. Дефект найден на этапе планирования двумя
независимыми проверяющими.

**Consequences:** Правило «пустое значение означает дефолт» держится только пока запись в данные
идёт через нормализацию, а поле не подменяет пустоту дефолтом. Любая будущая форма редактирования
названий обязана следовать тому же разделению.

**Tech debt introduced:** None

## [0011-feat-group-customization] Санитизация данных на каждой загрузке, а не только при миграции

**Date:** 2026-08-11
**Feature:** [0011-feat-group-customization]
**Status:** Accepted

**Context:** Новые поля — порядок групп и название — правятся руками в файле данных так же легко,
как остальные. Повреждённый порядок даёт пустой экран вместо доски.

**Decision:** Санитизация обоих полей вынесена в отдельный блок, выполняемый на каждой загрузке
вне версионных веток. Принимает значение любой формы: не массив и не строка приводятся к
безопасному значению, посторонние идентификаторы отбрасываются, повторы схлопываются, недостающие
дописываются.

**Rationale:** Санитизация только внутри версионной ветки чинила бы данные ровно один раз и не
спасала бы от повреждений, внесённых позже. Обработка только «правильных» форм оставляла бы
падение на значении `null` — тот самый исход, который блок и предотвращает.

**Consequences:** Гарантия честная, но узкая: она распространяется на два новых поля. Путь загрузки
в целом не тотален относительно испорченного файла — см. реестр техдолга.

**Tech debt introduced:** None (существующая неполнота зафиксирована отдельно)
